# Требования к annotator

Источник: сообщения владельца в сессии 2026-11-24 (исходное ТЗ, ответы на уточняющие вопросы, обратная связь после первого запуска).

## Назначение

CLI-аннотатор в unix-стиле: делает одно дело хорошо. Даёт проревьюить файл, как правило ответ или отчёт агента: показывает отрендеренный markdown, к выделенному фрагменту можно добавить комментарий (набирается с клавиатуры) или быструю отметку. Результат уходит дальше (агенту) как текст.

Ориентир по функциональности: plannotator (можно подглядывать). Особое внимание — UX и удобство работы с клавиатуры.

## Решения (ответы на вопросы)

| Тема | Решение |
| --- | --- |
| Жизненный цикл | Блокирующий CLI: `annotator file.md` поднимает локальный сервер, открывает браузер, ждёт «Finish», печатает аннотации в stdout и завершается. |
| Формат вывода | Markdown-фидбек (цитата + комментарий/метка), готов для вставки в промпт агенту. |
| Якорь аннотации | Произвольное выделение текста в отрендеренном markdown. |
| Управление | Курсор как в редакторе (стрелки, Shift — выделение, Alt — слова, Cmd — границы строки/документа). |
| Стек | Bun/TypeScript. |
| Быстрые отметки | Как в plannotator (его набор quick labels, у меток с tip текст инструкции уходит в фидбек). |
| Вердикт | Не нужен: только аннотации. Пустой вывод = замечаний нет. |
| Вход в MVP | Только файл по пути. |
| Интерфейс MVP | Только веб. |

## Обратная связь после первого запуска

1. Повторный `Remove` на той же области стакается. Владелец: «хз, может и норм». Статус: оставлено как есть, защита от дубля не делалась.
2. Карточки аннотаций справа должны выбираться: клик + клавиша, и выбор мышью. Статус: сделано (клик выделяет, `e` правка, `x` удаление, кнопки на карточке, `[`/`]`).
3. Левый сайдбар с outline документа. Статус: сделано (клик, `{`/`}`, `o`).

## Вне MVP (явно отложено)

stdin и несколько файлов; не-markdown (код, diff); сохранение незавершённой сессии; свои наборы меток; общий вердикт approve/changes; сборка единым бинарём (`bun build --compile`); другие интерфейсы кроме веба.

## Принципы

- unix-like: stdout только фидбек, статусы в stderr, коды выхода (0 готово, 1 отмена, 2 ошибка).
- Минимально необходимое: только то, что нужно сейчас, без задела на гипотетическое.
- Хоткеи по физическим клавишам (`e.code`), чтобы работали на любой раскладке (владелец печатает по-русски).
